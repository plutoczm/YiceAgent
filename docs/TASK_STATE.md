# 结构化会话任务状态

本项是用户选择的上下文改进，范围为目标、有效约束、纠正和待解决事项。它不增加 Agent 阶段，也不改变长期记忆确认、业务审批或模型调用预算。

## 数据与生命周期

TaskState 保存在 PostgreSQL 现有的私有 Result 记录中，按会话加锁后追加版本，不新增表或迁移。每条事实保存属性、类型、值、原文片段、消息 ID、来源位置、创建版本和失效关系。原始消息和旧状态版本保持可核对。

- active：当前有效要求。
- superseded：被明确纠正取代，记录新事实 ID 与结束版本。
- resolved：用户原文明确提及并解决的事项。
- 同属性不同值但没有明确替换关系：同时保留，在面板标出冲突。

状态限于所属会话，不能自动转为跨会话长期记忆。用户要求的预算也不能更改项目计费上限、工具权限、价格或支付确认。业务动作的确认状态每轮从业务服务读取，作为独立数据展示，不由模型提取或改变。

## 获取与校验

现有 Analysis 意图调用同时提出 task_updates，不新增无条件模型调用。通用目标、约束与待解决事项由模型提出带原文的候选，模型不能直接写版本、身份或权限。明确本会话或已校验的会话纠正不生成长期记忆候选；提议通过 Pydantic 与确定性来源校验后才采用；无效提议记录拒绝原因，之前状态保留。

规则保护层识别明确的人民币预算、回答语言和代号，以及含关键约束的原文分句。已知字段只有在明确纠正时才替换旧值；相等数值去重，提问中的数值不当作新预算。通用属性替换还须引用同属性事实，并在当前用户原文中明确提及旧要求。范围不清时保留冲突。解决事项须有明确解决表述与原事项引用。

这是带来源的数据整理，不保证所有自然语言语义都被正确识别。任意复杂意图、否定和混合要求仍需实际模型质量评测；原文存在只证明来源，不能证明模型对语义的理解一定正确。

## 上下文与摘要

模型输入只包含 active 状态；失效事实、完整纠正句和旧值留在私有历史视图。原始最近四轮仍按完整工具组保留，所以近期历史可以出现旧值，但当前有效状态明确给出优先采用的值。

较早摘要的输入投影移除失效来源分句，保留同一消息中其他目标与约束。生成摘要也只要求保留有效原文片段。较宽的引用必须来自同一原消息且包含全部保护片段，仍拒绝改写和遗漏；失败只报告原始上下文回退，不声称压缩成功。摘要历史版本不被改写。重复压缩按历史范围与有效来源片段去重，不因无关状态版本变化反复请求摘要。

当前值回忆会把选中的旧来源沿失效关系核对到有效来源，发布确切新片段；用户明确请求历史对比时仍可读取原历史。64条有效事实是额外保护上限；输入预算不足时停止并报告容量，不静默删除约束。8192应用窗口、1536输出、512安全余量与75%触发条件继续生效。

## 工作台与接口

上下文页面新增“当前会话任务状态”，展示有效字段、来源、创建版本、失效记录、冲突及独立业务确认状态。选择历史调用时，另可核对此调用采用的状态版本；当前状态和历史调用快照有明确区别。

GET /api/v2/conversations/{cid} 返回最新状态；GET /api/v2/conversations/{cid}/task-state 返回版本记录。两者均由服务端校验租户和用户归属。没有对外提供任意状态写入接口。
