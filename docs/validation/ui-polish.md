## Jev：当前核心不需要，保留可选对照实验

工程建议是先稳定现有上下文、记忆、检索及受限工具循环，不把 Jev 加入每轮关键路径。当前已有三条模型通道、真实 BGE 重排和确定性事实/权限/状态门禁；新增供应商会增加网络依赖、故障和额外调用。历史 Qwen 误分类/参数缺失说明意图环节有优化空间，但不能据此断言 Jev 一定改进。

Jev 的合适用途是封闭意图分类、记忆候选稳定性/相关性筛选，或辅助判断回答是否受到证据支持。官方提供 [意图路由模式](https://docs.typesafe.ai/patterns/intent-routing)。它本身不负责历史持久化、摘要版本、上下文裁剪、窗口预算或工具循环终止。长期记忆写入仍需用户确认。

实际应用需特别核对中文效果：[官方模型说明](https://docs.typesafe.ai/models) 明确英语表现最好，中文等 CJK 需要在自身资料上测试；模型版本/浮动 alias 也需记录。[confidence](https://docs.typesafe.ai/confidence) 来源于概率分布，是不确定性信号，不能当作事实正确或业务授权证明。金额、订单状态、确认审批、关键引用、token 计数与执行上限继续由确定性代码负责。

如果以后授权实验，优先做一个可关闭的旁路意图分类对比：使用历史失败样本和独立中文留出样本，固定模型版本，比较意图 macro-F1、应澄清/拒答的处理、危险误路由、整轮 P95 耗时、每完成 turn 成本及新增失败。先只记录判断，不影响业务执行；有实测收益才考虑替换部分现有分类调用。无需先替换 BGE Reranker，也不建议层层堆叠评审模型。

此段是建议，不是已实现计划。Jev 仍为 `NOT_RUN`，本任务没有 Jev 登录、API Key、安装或计费调用。没有提交、标签或推送。
